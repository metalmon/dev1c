# Правка окна по живому прогону — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Закрыть находки живого прогона 9.11: чтобы окно не показывало ответ, которого человек не давал, не звало за полями, которых нет на экране, и чтобы выбор выглядел выбором.

**Architecture:** Правки мелкие и разнородные, но делятся на четыре слоя: модель (что записывается при заведении карточки), слова (что человек читает), раскладка (подвал и вид кнопок выбора) и момент пересчёта (замок после правки). Каждая задача живёт в одном слое, и ни одна не трогает ход работы программы — ни транспорт, ни публикацию, ни запись настроек помимо названных ключей.

**Tech Stack:** Rust 2021, workspace `setup/`; крейт `onec-connect`; окно на GPUI через `gpui-kit`.

**Spec:** `docs/superpowers/specs/2026-11-09-window-live-pass.md` — двадцать находок с измерениями; спека интерфейса `2026-11-01-interface-design.md` остаётся высшей властью по правилам экрана.

## Global Constraints

- Слова на экране — обращением к человеку, без жаргона кода: ни «toml», ни имён полей, ни команд запуска.
- Отказ называет только то, что человек видит на ЭТОМ экране: если поля нет — звать за ним нельзя.
- Один словарь на одно понятие: слова ответов живут в `gui::link`, второй копии быть не должно.
- `rustfmt.toml`: `max_width = 140`. Гейты: `cargo test --workspace --lib`, `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`.
- Один `cargo` на машину в один момент: исполнитель гоняет свои модули, ревьюер `cargo` не запускает вовсе, полный прогон делает ведущий.
- Проверка глазом обязательна там, где правка про вид: снимок окна прикладывается к отчёту (как снимать — в разделе «Как проверялось» спеки прогона).

## Решения владельца 9.11 (не обсуждаются)

- **Высота окна считается от экрана и больше не скачет** (поправка владельца 9.11, отменяет первое решение «оставить как есть»): окно сразу открывается высоким — долей рабочей области экрана, — и всё, что не влезло, уезжает в прокрутку. Задача 7.
- **Вопрос на пустой «Связи» убирается совсем**: остаётся «Соединений пока нет» и две кнопки-ответа.
- **Переключатели остаются выпадающими**, но получают стрелку и вид поля выбора; слова ответов не сокращаются.

## Review Focus

1. Заведение карточки на пустом списке и на непустом — одно правило режима, без расхождения (задача 1).
2. Список из двух карточек разных ролей: обе под своими подписями, пустых подписей нет (задача 2).
3. Свежий комплект: ни одной строки в журнале до первого действия человека (задача 6).
4. Запертый замок: главная кнопка ведёт себя одинаково на всех вкладках (задача 4).
5. Карточка без своей базы: ни одно слово не зовёт заполнить поле, которого на экране нет (задача 5).

**Решение владельца 9.11:** «Мы в журнале уже делим сообщения тонкой чертой. Давай по философии Fluent туда по центру добавим временной интервал». Лестница — та, что предложил ведущий, владелец согласился: **«Сегодня» → «Вчера» → название дня недели для остальных дней этой недели («В понедельник») → дата для всего, что старше («3 ноября»)**. Вместе с датами владелец просил записать и склейку повторов.

Нового зависимого пакета для времени НЕ заводить: в этом же файле уже живёт `log::clock()`, берущая местное время через `GetLocalTime` (и свой запасной путь вне Windows) — дата берётся оттуда же, тем же приёмом.

    // «во вторник», «в среду», «в четверг», «в пятницу», «в субботу»,
    // «в воскресенье»); старше → «3 ноября»

Отрисовка вкладки идёт по чистому итогу («подпись дня» / «строка с числом повторов»), как уже сделано у вкладки «Связь» (`panel::Body`): отрисовка своего не решает.

Подпись дня — по центру, между тонкими чертами, которыми строки уже разделены. Повтор показывается в конце строки («×2») и не плодит новых строк.
