# Заплата 0001 к стенду разработки: рабочее место остаётся без инструментов 1С

Это письмо к файлу `patch.sh`. Прочитайте его целиком до запуска — заплата правит настройки рабочих мест и переустанавливает расширение в их базах.

## Кому нужна

Тем, у кого стенд поднят из комплекта, собранного **26.10.2026 или позже**. Признак беды: в редакторе агент не видит инструментов 1С — не читает метаданные, не выполняет запросы, не ходит в базу. Если инструменты работают, заплата не нужна, но и вреда не принесёт.

## Что сломано

Коннектор на стенде работает в локальном режиме: база лежит в том же контейнере, туннель никуда не поднимается, и адреса среды у него нет. Проверка настроек при этом требует такой адрес безусловно, и установка останавливается на первой же строке. Из-за этого у рабочего места нет ни проекта, ни публикации базы, ни расширения mcp-1c — а без расширения агенту неоткуда взять ни метаданные, ни данные.

Отказ при старте намеренно не роняет контейнер: стенд поднимается, рабочий стол открывается, и человек видит обычную среду с молчащим агентом.

## Что делает заплата

Дописывает в настройки каждого рабочего места одно поле — адрес-пустышку, которым проверка удовлетворяется. В локальном режиме его не читает никто: туннеля нет, обращений по нему нет. Затем заново проводит установку расширения в базу каждого рабочего места: это вызов конфигуратора 1С, минута-две на место.

Заплата не ходит в сеть, ничего не скачивает, не управляет докером, не спрашивает и не хранит паролей и ничего никуда не отправляет. Трогает только настройки рабочих мест и расширение в их базах. Копия настроек до правки остаётся рядом под именем `1c-connect.toml.before-0001`. Повторный запуск безвреден.

## Сверить файл до запуска

Сумма SHA-256 файла `patch.sh` указана в письме, которым он пришёл. Сверьте:

- Windows, PowerShell: `Get-FileHash .\patch.sh -Algorithm SHA256`
- Linux: `sha256sum patch.sh`

Не совпало — не запускайте, напишите нам.

## Как запустить

С машины, где поднят контейнер стенда, одной строкой:

```
docker exec -i dev1c sh -s < patch.sh
```

Если контейнер назван не `dev1c`, подставьте его имя (`docker ps` покажет). Если вы уже внутри стенда, в его терминале:

```
sh patch.sh
```

Разница одна: снаружи заплата проходит по всем рабочим местам сразу, изнутри — только по тому, от чьего имени запущена.

## Как выглядит успех

На каждое рабочее место — строка про правку настроек, затем установка и её проверка. В конце каждой проверки стоит «провалено 0»:

```
dev1: дописываю server = "localhost:3393" (копия: ….toml.before-0001)
dev1: установка расширения (конфигуратор, минута-две)

Пройдено 18, провалено 0. Отчёт: /home/dev1/.local/share/dev1c/last-check.txt
```

## Как проверить потом

В терминале рабочего места:

```
~/dev1c/1c-connect check
```

Должны быть пройдены факты «публикация отвечает» и «расширение в базе». Снаружи то же самое по всему стенду: `docker exec dev1c test-stand`.

Что приложено на этом стенде, видно так: `cat /home/dev1/.local/share/dev1c/patches.applied`.

## Если что-то пошло не так

Вернуть настройки: скопировать `1c-connect.toml.before-0001` обратно на место `1c-connect.toml`. Расширение в базе при этом останется — оно там и должно быть.

Пришлите нам вывод запуска и файл `/home/<рабочее место>/.local/share/dev1c/1c-connect.log` — по ним видно, на каком шаге остановились.

## Что дальше

Это временная мера. Правка уже внесена в программу: в локальном режиме адрес среды не спрашивается вовсе. Она придёт со следующим комплектом, и заплата ей не помешает — лишнее поле так и останется никем не читанным. Прикладывать её к новым стендам из нового комплекта не понадобится.
