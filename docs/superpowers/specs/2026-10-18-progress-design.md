# Ход долгих операций в `1c-connect`

Дата: 2026-10-18. Ветка `worktree-gpui-connect`, поверх спеки окна
`2026-10-16-gpui-connect-design.md` и этапа 6B (`flow.rs`, `local.rs`,
`project.rs`).

## Зачем

Первая выгрузка конфигурации (`cf_decompile` большой базы) идёт десятки
минут, первый push тысяч файлов — минуты, загрузка в базу (`cf_load`) и
установка расширения (Конфигуратор) — минуты. Платформа при этом молчит,
git в нашей обвязке зовётся с `-q` и читается целиком по завершении. Человек
видит кнопку в состоянии «loading» и не знает, идёт ли процесс или всё
повисло. Нужно, чтобы в любой момент было видно: **что** идёт, **сколько**
уже идёт, **есть ли признаки жизни**, и по возможности **сколько осталось**;
а если жизни нет — чтобы можно было прервать.

## Цели

- Во время любой долгой операции окно показывает фазу, прошедшее время с
  секундным тиком и последнюю активность; трей показывает то же в подсказке
  и значком «занят».
- Там, где прогресс измерим, полоса определённая: выгрузка конфигурации по
  числу файлов (со второго раза — в процентах от прошлого), push/pull по
  процентам git.
- Отсутствие активности дольше порога видно явно, и операцию можно прервать
  там, где прерывание безопасно.
- По окончании, если окно спрятано, системное уведомление Windows.
- Командная строка (`1c-connect export|import|install`) получает те же
  фазы и счётчики строками, без отдельного кода.

## Не-цели

- Прогресс операций агента из Zed (`project_push`, `cf_load` через мост):
  они идут под тем же мьютексом, но их ход окно не показывает; показывается
  только «занято агентом: <что>». Полноценный показ — отдельная работа.
- Проценты у `cf_load` и у установки расширения: платформа их не даёт.
  Для них — фаза, время, активность.
- Очередь операций. Как и сейчас: вторая операция получает «занято».
- Оценка «осталось N минут» по скорости — только проценты и счётчики.

## Анти-цели

- Опрос по таймеру там, где есть событие. Таймер допустим только для
  счётчика файлов (платформа не сообщает о записи файлов) и для секундного
  тика часов.
- Разбор человекочитаемых логов платформы ради чисел. Берём только то, что
  даёт стабильный формат: число файлов на диске и строки прогресса git.
- Прерывание, которое оставляет базу в полусостоянии. `cf_load` и установку
  расширения прервать из окна нельзя.

## Что есть сейчас (зависимости)

| Часть | Как работает | Что мешает |
|---|---|---|
| `flow::export_with(d: &Deps, message, log)` | `lock()` мьютекса проекта → `log("cf_decompile → src …")` → `d.call("cf_decompile", {OUT: src, background: false})` → `d.push(message)` | фазы есть только как строки журнала; у `Deps` нет канала прогресса |
| `flow::import_with(d, log)` | `lock()` → проверка `1cv8.exe` → `d.pull()` → `d.call("cf_load", {SRC: src, increment})` | то же |
| `flow::with_real(ctx, f)` | собирает `Deps` из `local::call` (таймаут 3600 с), `project::push/pull`, `bridge::configurator_count`; `log = ctx.say` | единственное место, где известны и проект, и процесс |
| `local::call(cmd, tool, args, timeout, on_log)` | поток-читатель stdout, `recv_timeout`, строки `notifications/message` → `on_log`, по таймауту/выходу — `child.kill()`; дочерний процесс в Job Object | нет способа прервать снаружи; `on_log` получает текст vrunner, формат строк не стабилен |
| `project::push/pull` | `git(p, args)` = `Command::output()` целиком, `push -q`, `pull --rebase` | ни одной строки до конца; `-q` гасит прогресс |
| `ops_host::Extension::apply` | `docker::exec(ctx, mcp-1c, --install …)` — Конфигуратор, минута-две; `Event::Output` в конце | только фаза и время |
| `gui::run_op(cx, which)` | поток + `guarded()`, `Ev::Line` по ходу, `Ev::Done` в конце; `Busy::{Ext,Project,Check}` | «занято» без фазы, времени и чисел |
| `gui::panel` | карточка состояния = туннель; кнопки `loading` при `busy`; тик 30 с | негде показать ход |
| `gui::tray` | значок с бейджем по туннелю, подсказка | не знает про операции |
| `project::LOCK` / `doing()` | один процесс на проект; `doing()` называет инструмент моста, который идёт | окно не показывает, что мост занят |
| `main.rs` CLI `export|import|install` | тот же `flow`/`apply_all`, события в stdout | строки есть, счётчиков нет |

## Решения

### Модель: одно событие хода

```rust
// common или 1c-connect::flow — общий для окна и CLI
#[derive(Clone, Debug, PartialEq)]
pub struct Progress {
    pub phase: Phase,                 // что идёт
    pub done: Option<u64>,            // сделано (файлов, объектов)
    pub total: Option<u64>,           // всего, если известно
    pub note: String,                 // последняя строка активности, уже затёртая
}
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Phase { Decompile, Push, Pull, Load, Install, Uninstall, Check }
impl Phase { pub fn title(self) -> &'static str }
// «Выгружаю конфигурацию», «Отправляю в git», «Получаю из git», «Загружаю в базу»,
// «Устанавливаю расширение», «Снимаю расширение», «Проверяю»
impl Phase { pub fn cancellable(self) -> bool }  // Decompile, Push, Pull, Check — да; Load, Install, Uninstall — нет
```

`Deps` получает `pub progress: &'a dyn Fn(Progress)`; `export_with` /
`import_with` зовут его в начале каждой фазы (`Progress { phase, done: None,
total: None, note }`) — это **единственная** правка их логики, тесты с
`Fake` проверяют порядок фаз. `with_real` строит `progress` из `ctx`:
`Event::Progress(Progress)` — новый вариант `common::Event`, который
`kit.journal` не пишет (это не факт, а пульс), CLI печатает одной строкой
при смене фазы и раз в 30 с для счётчиков, окно превращает в `Ev::Progress`.

### Источники чисел

**Файлы выгрузки.** В `with_real` на время `call("cf_decompile")` живёт
поток-счётчик: раз в 2 с `walkdir`-подобный обход `<проект>/src`
(`std::fs::read_dir` рекурсивно, без новой зависимости), число файлов →
`progress(Progress { phase: Decompile, done: Some(n), total })`. `total` —
число файлов прошлой выгрузки из состояния комплекта
(`Kit::state_get("export.files")`), после удачной выгрузки записывается
заново. Первая выгрузка: `total: None`, полоса неопределённая, текст
«выгружено 3 410 файлов»; вторая: «3 410 из 7 902, 43 %». Счётчик
останавливается, когда `call` вернулся. Обход 8 000 файлов на SSD — доли
секунды раз в 2 с, на HDD заметно, поэтому интервал растёт до 5 с, если
обход занял больше 500 мс.

**git push / pull.** `project::push` и `pull` переводятся на потоковый
вызов для одной команды каждая: `git push --progress …` и `git pull
--rebase --progress …` через `spawn` с `stderr` в трубу, строки читаются по
`\r` и `\n`; остальные команды (`add`, `commit`, `rev-parse`, `status`,
`ls-remote`) остаются на `output()`. Разбор строк чистой функцией
`git_progress(line) -> Option<(u64, u64)>` по образцам
`Writing objects:  45% (1234/2740)`, `Receiving objects: …`,
`Compressing objects: …`, `Resolving deltas: …`; `Counting objects`
пропускается. Итоговый текст и ошибки собираются как раньше и затираются
`redact_text` до журнала. `-q` убирается только у этих двух команд.

**cf_load, установка и снятие расширения, проверка.** Только фаза, время
и последняя строка. Для `cf_load` строкой активности служат
`notifications/message` от vrunner (они уже идут в `on_log`); для
`mcp-1c --install` — ничего, кроме часов (процесс молчит до конца).

### Жизнь и застой

`Ui.progress: Option<Running>`:

```rust
pub struct Running { pub which: Which, pub started: Instant, pub last: Progress, pub seen: Instant }
```

`seen` обновляется каждым `Ev::Line` и `Ev::Progress` операции. Тик окна
во время `progress.is_some()` — 1 с (сейчас 30 с), чтобы часы шли. Если
`seen.elapsed() > 5 мин` — карточка добавляет «нет новостей 5 мин» жёлтым
и, если `phase.cancellable()`, кнопку «Прервать».

### Прерывание

`Deps` получает `pub cancel: &'a AtomicBool`. `local::call` получает
`cancel: Option<&AtomicBool>` и проверяет его в своём цикле `recv_timeout`
(шаг 1 с): взведён — `child.kill()`, `Err("прервано")`. Потоковый git
тоже: взведён — `kill`, `Err("прервано")`. Мьютекс проекта освобождается
по `drop` защёлки, как при любой ошибке. В окне флаг лежит в
`Ui.cancel: Arc<AtomicBool>`, «Прервать» взводит его; после `Ev::Done`
создаётся новый. Прерванная выгрузка оставляет `src` неполным — это
безопасно: следующая `cf_decompile` перезапишет; прерванный push безопасен
по определению git. Для `Load`/`Install`/`Uninstall` кнопки нет и флаг не
читается.

### Поверхности

- **Карточка состояния** во время операции становится карточкой хода:
  кружок жёлтый («занят»), заголовок `phase.title()`, подстрока
  «12 мин 05 с · выгружено 3 410 файлов» или «45 % (1234/2740)», ниже
  `Progress` из `gpui-component` (`value` при `total`, иначе `loading`),
  последняя строка активности 13 px приглушённым, при застое — «нет
  новостей N мин» и «Прервать». Переключатель туннеля остаётся, но
  `disabled` (связь нужна операции). По `Ev::Done` карточка возвращается к
  туннелю.
- **Подвал**: главная кнопка вкладки в `loading`, как сейчас; меню «…»
  `disabled`.
- **Трей**: `Tray::set_busy(Option<&str>)` — жёлтый кружок вместо
  зелёного/серого и подсказка «1c-connect: выгружаю конфигурацию, 12 мин»;
  обновляется раз в минуту (подсказка), значок — при смене состояния.
- **Журнал**: как сейчас, плюс строка на каждую фазу (`Kind::Say`,
  `phase.title()`) и итог («выгрузка завершена: 3 410 файлов, 14 мин»).
- **Уведомление Windows** по `Ev::Done`, если `Ui.window.is_none()`:
  `SystemNotification { tag: "op", title: "1c-connect", body: итог или
  текст ошибки }` через GPUI (`App`-метод публикации уведомления — см.
  `gpui-pre-0.3.9/src/app.rs`, имя уточняет строитель; если на Windows
  GPUI уведомления не реализованы — `Shell_NotifyIconW` с `NIF_INFO` через
  `tray-icon` недоступен, тогда всплывашку даёт сам трей:
  `muda`/`tray-icon` не умеют, и уведомление откладывается с пометкой в
  STATUS).
- **Занято агентом**: если `project::doing()` не пусто, а своей операции
  нет, карточка показывает «занято агентом: project_push» с часами от
  момента, когда это заметили (опрос `doing()` раз в секунду только пока
  окно открыто — исключение из анти-цели, потому что мост не шлёт событий
  в окно; дешевле, чем тянуть канал через `bridge`).

### CLI

`main.rs` для `export|import|install`: `Event::Progress` печатается так —
смена фазы: `== Выгружаю конфигурацию`; счётчик: раз в 30 с
`   выгружено 3 410 файлов` или `   45 % (1234/2740)`; застой 5 мин:
`   нет новостей 5 мин`. Ctrl+C уже останавливает процесс; флаг `cancel`
CLI не использует.

### Что меняется по файлам

| Файл | Правка |
|---|---|
| `common/src/lib.rs` | `Event::Progress(Progress)`, `Progress`, `Phase`; `kit.journal` его не пишет |
| `1c-connect/src/flow.rs` | `Deps { progress, cancel }`, вызовы фаз, счётчик файлов в `with_real`, запись `export.files` |
| `1c-connect/src/local.rs` | параметр `cancel`, проверка в цикле |
| `1c-connect/src/project.rs` | `push`/`pull` потоково с `--progress`, `git_progress`, `cancel` |
| `1c-connect/src/gui/mod.rs` | `Ui.progress`, `Ui.cancel`, `Ev::Progress`, `run_op` передаёт флаг, `Ev::Done` → итог, уведомление, `set_busy` |
| `1c-connect/src/gui/panel.rs` | карточка хода, тик 1 с при занятости, «Прервать» |
| `1c-connect/src/gui/tray.rs` | `set_busy`, жёлтый бейдж |
| `1c-connect/src/main.rs` | печать `Event::Progress` |
| `bridge.rs` | не меняется (агент идёт своим путём; `doing()` уже есть) |
| `dev1c-setup` | не меняется (`Event::Progress` для него просто новый вариант, печатается как `Say`) |

### Проверки

- `flow`: `Fake` получает `progress` и `cancel`; тесты: фазы идут в порядке
  `Decompile → Push` и `Pull → Load`; взведённый `cancel` до `call` даёт
  «прервано» и не зовёт `push`.
- `project::git_progress`: таблица строк git → числа; строка без процентов →
  `None`.
- Счётчик файлов: чистая функция `count_files(dir)` на временном каталоге
  с вложенностью; `export.files` пишется только после `Ok`.
- `gui`: чистые `progress_text(&Running, now) -> (title, sub)` и
  `is_stale(&Running, now)`; `Ev::Progress` обновляет `seen`; `Ev::Done`
  очищает `progress` и создаёт новый `cancel`.
- Живой прогон: выгрузка демо-базы с окном открытым и спрятанным (часы
  идут, счётчик растёт, уведомление приходит), «Прервать» на push
  (мьютекс свободен после, повторный push проходит).

## Риски и допущения (проверить до плана)

1. Формат строк прогресса git на Windows (`--progress` в stderr с `\r`) —
   стандартный, но проверить на `git` из комплекта инструментов.
2. Пишет ли vrunner-mcp `notifications/message` во время `cf_decompile`
   (нужны как «последняя активность» для `cf_load`; для выгрузки хватит
   счётчика файлов). Если молчит — активность у `Load` только часы.
3. Есть ли у GPUI на Windows публикация `SystemNotification`; если нет —
   уведомление откладывается, остальное не зависит.
4. Обход `src` раз в 2 с на медленном диске во время записи платформой —
   не мешает ли записи (только чтение каталога; риск мал).
5. `Event::Progress` в `common` затрагивает `dev1c-setup` (новый вариант в
   `match` по `Event` в его `main.rs`): одна строка.
