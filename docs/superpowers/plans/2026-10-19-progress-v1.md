# Ход долгих операций в `1c-connect` (v1) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** во время любой долгой операции `1c-connect` окно показывает фазу, прошедшее время и признаки жизни, трей показывает «занят», по окончании при спрятанном окне приходит уведомление Windows, а `git push`/`pull` можно прервать.

**Architecture:** фаза — новое событие `Event::Progress` в `common`, которое порождает `Runner` (поток `flow`, установка расширения, проверка) и которое печатает CLI и ловит окно. Окно держит `Ui.progress: Option<Running>` (фаза, старт, последняя активность), перерисовывается секундным тиком уровня приложения, а не на каждое событие. Прерывание — флаг `AtomicBool`, который `project::push/pull` проверяют вокруг своих команд git.

**Tech Stack:** Rust, `common` (события), `gpui-kit 0.7.3` (окно, `App::set_app_identity`, `App::show_system_notification`), `tray-icon 0.26`, `std::process::Command::spawn` + `try_wait`.

**Spec:** `docs/superpowers/specs/2026-10-18-progress-design.md` (v1; раздел «Полоса хода» уже сделан задачей 17 ветки GPUI; v2 и «Долг» — не в этом плане).

## Global Constraints

- Сборка и тесты — **только в CI** (`gh workflow run build.yml --ref <ветка> -f binaries_only=true`); локально `cargo` не запускать (ноутбук).
- Новых зависимостей нет; версии крейтов пинованы точно (`gpui-kit = "=0.7.3"`, `tray-icon =0.26.1`).
- `bridge.rs`, `local.rs` в v1 не меняются; `local::call` остаётся с таймаутом 3600 с.
- Никакого опроса по таймеру, кроме тика часов: 1 с при операции, 30 с без неё.
- Прерывание только у `git push`/`git pull`; «Прервать» видна только при `Phase::{Push, Pull}`.
- Тексты фаз (`Phase::title`), дословно: «Выгружаю конфигурацию», «Отправляю в git», «Получаю из git», «Загружаю в базу», «Устанавливаю расширение», «Снимаю расширение», «Проверяю». Итог прерывания — строка `Kind::Warn` «прервано».
- Секреты: всё, что идёт в журнал и в `1c-connect.log`, проходит `common::docker::redact_text`, как сейчас в `project::git`.
- Три `match` по `Event` вне окна остаются исчерпывающими (без `_ =>`).
- Коммиты: `GIT_AUTHOR_NAME=OktaPlus`, `GIT_AUTHOR_EMAIL=oktacoder@gmail.com` (и те же `GIT_COMMITTER_*`), сообщение файлом `-F`, трейлер `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. **Паника внутри операции** (`guarded` шлёт `Ev::Done`): `progress` должен очиститься и флаг `cancel` смениться на новый — иначе следующая операция стартует с «занят» в карточке. Тест — Task 4 («Done очищает progress и создаёт новый cancel»).
2. **«Прервать» нажато, когда push уже закончился** (фаза ушла дальше или операция завершилась): флаг взведён, но ничего не бежит; следующая операция не должна унаследовать взведённый флаг. Тест — Task 4 (новый `cancel` на `run_op`).
3. **Тихая выгрузка**: Конфигуратор молчит 20 минут, `seen` не двигается — карточка обязана показать «нет новостей N мин» от `seen`, а не от `started`. Тест — Task 4 (`is_stale`).
4. **Окно спрятано на всю операцию**: тик продолжает идти, подсказка трея обновляется, уведомление приходит ровно один раз на `Done`. Тест — Task 5 (`tray_tooltip`, `tray_state`); живой прогон — Task 7.
5. **Прерванный push не ломает проект**: замок свободен, повторный push проходит. Тест — Task 3 (push с взведённым флагом → «прервано», затем push без флага → отправлено).
