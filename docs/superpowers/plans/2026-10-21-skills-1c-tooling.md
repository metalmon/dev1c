# Процессные скиллы под 1С: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** На каждом шаге процесса (спека, план, тесты, проверка, ревью,
отладка) агент в стенде знает, каким инструментом 1С собирать факты и каким
проверять результат, а неработающие инструменты ему недоступны.

**Architecture:** Карта «потребность → инструмент» живёт в одном файле —
`config/agents-global.md`, который укладывается как `~/.config/zed/AGENTS.md`
и попадает в контекст всегда. Шесть процессных скиллов получают по короткому
блоку, который называет инструменты шага и доказательство, и ссылается на
карту вместо копирования. Лишние инструменты гасятся профилями агента Zed.

**Tech Stack:** Markdown (скиллы и AGENTS.md), JSONC (`zed-settings.json`),
POSIX sh (`test-skills.sh`). Кода нет; проверки — греп, разбор JSON и
сборочный тест ключей в контейнере с настоящим бинарём Zed.

**Spec:** `docs/superpowers/specs/2026-10-21-skills-1c-tooling-design.md`

## Global Constraints

- Все файлы — UTF-8 **без BOM** и с **LF**. BOM перед `---` означает, что
  скилл не загрузится вовсе (`config/normalize-skills.py`).
- Frontmatter скиллов (`---` … `---`) не трогать: значения, начинающиеся с
  `[`, рушат разбор всего блока.
- Блоки в скиллах — **по-русски внутри английского текста**; upstream не
  переводить.
- Карта не перечисляет функции платформы. Проверено: перечень в промпте не
  переносится на незнакомые задачи (+5.7 pp при SE ±11).
- Ни одна формулировка не привязана к версии платформы: версия, корпус
  справки и режим совместимости приходят с проектом.
- Инструменты профиля `workspace` анализатора (`graph`, `metadata`,
  `outline`, `symbol_info`) в карту **не вносятся** — у агента их нет.
- Инвариант справки: «Сущность платформы не найдена» значит «такого имени в
  1С нет» при любом корпусе. Описания могут отсутствовать.
- `its_help` отключается явным `false`; `fetch`, `search_web`, `delete_path`,
  `copy_path`, `move_path` — невнесением в список (встроенные инструменты в
  профиле Zed работают как белый список).
- Образ пересобирает владелец в CI. Локально проверяется всё, кроме живого
  Zed.

## Review Focus

Что спека подразумевает, но ни один шаг плана сам не проверяет:

1. **Агент читает только AGENTS.md и не открывает скилл.** Карта обязана быть
   самодостаточной для шага «проверь перед отдачей»: порядок oscript →
   diagnostics → validate_syntax_check должен читаться без скиллов. Проверка —
   в задаче 1.
2. **Агент применяет `oscript -check` к модулю конфигурации** и получает ворох
   ложных ошибок на исправном коде. Запрет должен стоять в той же строке, что
   и разрешение, а не в соседнем абзаце. Проверка — в задаче 1.
3. **Сервер `1c` или `vrunner` не отвечает** (канал не поднят). Формулировки
   не должны обещать инструмент безусловно: ошибка подключения значит «канала
   нет», а не «инструмент сломан». Проверка — в задаче 1.
4. **Тестового фреймворка в базе нет**, а скилл TDD требует тест. Блок должен
   давать честный путь (oscript + validate_syntax_check) и запрещать называть
   это тестом. Проверка — в задаче 2.
5. **Правка роняет сборку образа** на неизвестном ключе `settings.json`.
   Проверка — в задаче 3, тем же гейтом, что в сборке.

**Files:**

**Interfaces:**

- Produces: во всех шести файлах заголовок `## Инструменты 1С на этом шаге`.

- [ ] **Шаг 1: Прогнать проверку и убедиться, что она падает**

```sh
for s in brainstorming writing-plans test-driven-development \
         verification-before-completion requesting-code-review \
         systematic-debugging; do
  F=config/skills/$s/SKILL.md
  grep -q '^## Инструменты 1С на этом шаге' $F || echo "нет блока: $s"
  grep -q 'Какой инструмент на каком шаге' $F   || echo "нет ссылки: $s"
done
```

Expected: шесть «нет блока» и шесть «нет ссылки».

- [ ] **Шаг 2: Написать блок в каждый из шести**

Содержание каждого — строка таблицы «Решение / 2» спеки. Требования,
одинаковые для всех шести:

- заголовок ровно `## Инструменты 1С на этом шаге`, перед секцией красных
  флагов (где она есть), иначе в конце файла;
- 5–15 строк, по-русски;
- называет инструменты и **доказательство** шага, а не пересказывает справку;
- ссылается на карту словами «Какой инструмент на каком шаге» в AGENTS.md;
- в `test-driven-development` — честный путь: фреймворка в базе нет, поэтому
  алгоритмика проверяется `oscript -check` и `oscript`, модуль —
  `diagnostics` и `validate_syntax_check`, и это **проверка, а не тест**;
  Iron Law не отменяется: сначала ожидаемое поведение, потом код. Абзац
  написать так, чтобы установка YAxUnit в CI заменила его целиком, не задевая
  остального;
- в `verification-before-completion` — таблица доказательств: «компилируется»
  = код возврата `validate_syntax_check`, не чистый LSP; «тесты прошли» =
  отчёт `test_*`; «загружено» = результат `cf_load`; «ничего не потеряли» =
  `project_status` без расхождений.

- [ ] **Шаг 1: Прогнать сборочный гейт и убедиться, что он проходит ДО правки**

Это базовая линия: гейт должен быть зелёным сейчас, иначе падение после
правки ничего не докажет.

```sh
docker run --rm --network=none -v "$PWD/config:/cfg:ro" \
  --entrypoint sh oktaplus/dev1c-1c:latest -c '
  for k in $(grep -oE "^[[:space:]]*\"[a-z_.]+\"[[:space:]]*:" /cfg/zed-settings.json \
             | tr -d " \":" | sort -u); do
    case "$k" in custom|bsl|bsl-reference|1c|vrunner) continue ;; esac
    grep -aq "$k" /opt/zed.app/libexec/zed-editor || echo "неизвестный: $k"
  done'
```

Expected: пусто (проверено 2026-10-21).

- [ ] **Шаг 2: Добавить профили в секцию `"agent"`**

Два профиля своими id (не правкой штатных `write`/`ask`):

- `"разбор"` — `name` «1С: разбор». `tools`: перечислить только читающие —
  `read_file`, `grep`, `find_path`, `list_directory`, `diagnostics`, `skill`.
  `enable_all_context_servers: true`, и в `context_servers` погасить
  `bsl-reference.its_help`, `vrunner.cf_load`, `vrunner.project_push`,
  `vrunner.infobase_update`, `vrunner.cache_show`, `vrunner.cache_clear`.
- `"работа"` — `name` «1С: работа». `tools`: то же плюс `edit_file`,
  `write_file`, `create_directory`, `terminal`, `spawn_agent`.
  `enable_all_context_servers: true`, погасить `bsl-reference.its_help`,
  `vrunner.cache_show`, `vrunner.cache_clear`.
- `"default_profile": "работа"` в секции `"agent"`.

Встроенные работают белым списком (`tools.get(name) == Some(&true)`), поэтому
`fetch`, `search_web`, `delete_path`, `copy_path`, `move_path` просто не
вносятся. Каждый профиль — с комментарием, зачем он, в стиле файла.
