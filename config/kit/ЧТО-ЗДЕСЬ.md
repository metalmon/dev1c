# Комплект dev1c

Здесь две части, и у них разные адресаты. Их не нужно ставить на одну
машину и не нужно ставить по порядку: они про разные компьютеры.

## server-linux — администратору сервера, один раз

Поднимает среду разработки на сервере: рабочие места по RDP, репозитории,
агентов и локальную модель.

| файл | что это |
| --- | --- |
| `dev1c-setup` | программа установки, весь разговор идёт через неё |
| `УСТАНОВКА.md` | порядок действий и что нужно до начала |
| `dev1c-image.tar.gz` | образ среды: рабочий стол, редактор, Gitea |
| `dev1c-1c-image.tar.gz` | образ стенда 1С: платформа и инструменты |
| `dev1c-1c-payload.tar.gz` | **том**: сама платформа 1С и демо-база |
| `nvidia-container-toolkit/` | пакеты, без которых контейнер не видит карту |

Почему архивов три, а не один. Образы несут программы, а платформа 1С с
демо-базой приезжает отдельно, томом: её дистрибутив лицензионный, в
сборку образа он не попадает. Поэтому на сервере сначала загружаются
образы, потом в тома вносится платформа.

**Чего здесь нет:** файла модели (`.gguf`) и движка Docker. Модель
выбирается под видеокарту сервера и приносится отдельно; Docker ставится
до начала, см. `УСТАНОВКА.md`.

## connector-windows — разработчику 1С, на флешку

Ставится на ту машину, где живёт 1С. Связывает её базу со средой: выгружает
конфигурацию в файлы, показывает агенту и возвращает правки обратно.

| файл | что это |
| --- | --- |
| `1c-connect.exe` | программа, она же окно в трее |
| `mcp-1c-windows-amd64.exe` | доступ агента к живой базе |
| `MCP_HTTPService.cfe` | расширение, которое ставится в базу |
| `vrunner/`, `git/` | инструменты, которые программа разложит на машину |

Файл параметров `1c-connect.toml` программа напечатает сама:
`1c-connect example`. Заполняются в нём адрес среды, рабочее место и
пароль к нему, путь к базе и имя пользователя базы с правами
администратора.

Пароль у пользователя базы может быть пустым, а имя — нет: с пустым
именем конфигуратор откажется работать, и причина будет выглядеть
загадочно.

После правки — `1c-connect check`: программа скажет, чего ей не хватает.
