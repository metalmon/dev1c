# Окно `1c-connect` на GPUI

Дата: 2026-10-16. Ветка `worktree-gpui-connect`. Спайк, на котором проверены
решения, лежит в `spike-gpui/` той же ветки и в репозиторий не входит
(одноразовый код, удаляется после переезда).

## Зачем

Окно `1c-connect` сегодня — Tauri 2 поверх WebView2 (`setup/1c-connect/ui/`,
`gui.rs`). Заказчик хочет **лучший вид**, и конкретно — вид Zed: машина
разработчика живёт в Zed, `1c-connect` — мост к ней, и окно должно выглядеть
как часть того же редактора, а не как веб-страница в рамке. Zed рисует себя
GPUI; берём тот же движок и ту же тему, что стоит у разработчика
(расширение `macOS Classic`, см. `config/zed/settings.json`).

Побочный выигрыш: уходит зависимость от WebView2 Runtime и костыль с фокусом
(ожидание 250 мс после `Focused(false)`, потому что WebView2 перехватывает
фокус при первом показе).

## Цели

- `1c-connect` без аргументов открывает окно на GPUI: тот же флайаут у трея,
  та же компоновка (шапка со статусом и переключателем, четыре вкладки,
  нижняя плашка), те же команды и события, что и сейчас.
- Вид — палитра темы `macOS Classic` из Zed (светлая и тёмная), шрифты
  Zed (IBM Plex Sans для интерфейса, Lilex для журнала), а устройство окна
  — по Fluent Design Windows 11: слои вместо теней, скругления 4/8 px,
  сетка отступов 4/8/12/16/24, рампа типографики, light dismiss. Тема
  по умолчанию системная; выбор руками — подменю «Тема» в меню трея
  (решение заказчика 2026-10-16), выбор запоминается.
- Трей с теми же пунктами и значком-бейджем, что сейчас.
- Сборка и CI: Windows — с окном, Linux — `--no-default-features`, как и
  сейчас. Без новых системных зависимостей на сборочной машине.

## Не-цели

- `dev1c-setup` не трогаем: остаётся на Tauri. Переезжает вторым заходом по
  готовому образцу, когда этот будет принят.
- Новых функций в окне нет. Поля проекта (этап 6B) появляются не здесь.
- Раздел настроек — потом. Выбор темы в него не входит: он в трее.

## Анти-цели

- Окно, которое «похоже на Zed, но свой стиль»: кнопки-пилюли, тени,
  градиенты, крупные скругления — не наше. Если сомневаешься, смотри, как
  это нарисовано в Zed.
- Логика развёртывания в окне. Окно зовёт те же операции и проверки, что
  командная строка, и рисует события — как и сейчас.
- Опрос по таймеру там, где есть событие.

## Ограничения

- Сборочная машина: Windows с VS Build Tools и Windows SDK (у GPUI шейдеры
  компилирует `fxc`/`dxc` из SDK — на этой машине и на `windows-latest`
  GitHub они есть). cmake и nasm не нужны. Первая сборка GPUI долгая
  (на этой машине около 10 минут), инкрементальная — секунды.
- Два окна-подсистемы, как сейчас: релиз `windows_subsystem = "windows"`,
  консоль для команд возвращает `common::console::attach`. В отладочной
  сборке консоль есть всегда — это удобно для `eprintln!`, но учти при живом
  тесте флайаута: окно conhost, появляясь, забирает фокус и прячет флайаут
  (см. «Спайк»).
- Версии крейтов пинуются точно: GPUI на crates.io живёт семейством
  `gpui-pre-*`, которое двигается вместе, и `gpui-kit` пинует согласованный
  набор. Обновление — осознанный шаг со сборкой и живым тестом, не
  `cargo update`.

## Решения

### Движок и виджеты

`gpui-kit = "=0.7.3"` — одна зависимость: GPUI (`gpui-pre 0.3.9`),
`gpui-component 0.7.3` (виджеты), `gpui-kit-assets` (значки).
`use gpui_kit::prelude::*; use gpui_kit::*;` — это GPUI;
`gpui_kit::component::{button, input, switch, tab, ...}` — виджеты.

Виджеты из `gpui-component`: `Button` (`.primary()` для главного действия
вкладки, остальные — обычные, то есть `secondary`), `Switch`, `TabBar`/`Tab`
в варианте по умолчанию (`Tab`: коробочки, активная сливается с телом —
как вкладки Zed), `Input`/`InputState` для полей (пароли — `.masked(true)`),
`Select` для рабочего места (сейчас `<select>`), `div().id(..).overflow_y_scroll()`
для журнала. Рисовать свои виджеты не надо.

### Тема и шрифты

Файл `setup/1c-connect/theme/macos-classic.json` в формате тем
`gpui-component` (`ThemeSet` → `themes[]` с `mode`, `font.*`, `radius`,
`colors`). Цвета перенесены из `huacnlee/zed-theme-macos-classic`
(`themes/macos-classic.json`, MIT): светлая и тёмная. Соответствие ключей
Zed → `gpui-component` зафиксировано в спайке (`spike-gpui/zed-macos-classic.json`)
и переносится как есть; там, где у темы Zed значения нет (акцент, успех,
ошибка в тёмной), взяты приглушённые тона: акцент стальной синий
(`#3F7CC6` тёмная, `#2F6BD1` светлая), успех и ошибка из терминальной
палитры самой темы (`#62BA46`/`#2E9E2C`, `#D9564E`). Кольца фокуса у
полей нет: `Input::focus_bordered(false)`, `ring` в теме прозрачный, а у активного поля ввода —
только акцентная линия 2 px снизу, как `input:focus` в прежнем `app.css`
(решение заказчика 2026-10-18; 2026-10-16: яркие подсветки — моветон).

Шрифты встраиваются в бинарь: `IBMPlexSans-Regular.ttf`,
`IBMPlexSans-SemiBold.ttf`, `Lilex-Regular.ttf` из `assets/fonts` репозитория
Zed (лицензия OFL, файл лицензии кладётся рядом в
`setup/1c-connect/fonts/`). Регистрация —
`cx.text_system().add_fonts(...)` до `gpui_kit::init`. Размер шрифта 15,
моно 14, радиус 4 (`radius.lg` 8), `shadow: false` — см. раздел «Fluent».
Прибавка к бинарю около 600 КБ.

Загрузка при старте:
`ThemeRegistry::global_mut(cx).load_themes_from_str(include_str!(..))`,
затем `Theme::global_mut(cx).light_theme/dark_theme` ← эти две темы,
`Theme::sync_system_appearance(None, cx)`.

**Выбор темы — в меню трея.** Подменю «Тема» с тремя пунктами-галочками
(`muda::CheckMenuItem`, ведут себя как радиокнопки: отмечен ровно один):
«Системная», «Светлая», «Тёмная». Выбор пишется в состояние комплекта
(`Kit::state_set("theme", "system" | "light" | "dark")`) и читается при
старте; нет записи — «Системная». Применение: «Светлая»/«Тёмная» —
`Theme::change(mode, None, cx)`; «Системная» —
`Theme::sync_system_appearance(None, cx)` сейчас и при каждом открытии
окна (`Panel::new`), чтобы смена темы Windows подхватывалась без
перезапуска. Окно перерисовывается само (`Theme::change` обновляет все
окна).

### Fluent: как окно ведёт себя и как сложено

Цвета — из Zed, а устройство окна — по Fluent Design (Windows 11): это
окно живёт на панели задач Windows рядом с быстрыми настройками, и человек
ждёт от него тех же повадок. Решение заказчика 2026-10-16 про Fluent для
Tauri-варианта остаётся в силе, меняется только палитра. Правила ниже —
не вкусовщина, а чек-лист для ревью вида.

**Слои (layering), а не рамки.** Fluent строит глубину слоями: подложка
окна (`background`), на ней карточки-слои (`secondary` — в тёмной теме чуть
темнее подложки, в светлой — белее), на слоях — элементы управления.
Граница слоя — обводка 1 px низкой непрозрачности (`border`), не тень.
Теней нет нигде (`shadow: false`); единственное исключение — само окно
флайаута, которое отделяет от рабочего стола системная тень окна и рамка
1 px `window.border`. Карточка статуса, строки списка операций и проверок,
поля ввода — всё это слои на подложке; плашки шапки и подвала — не слои,
а зоны подложки другого тона (`title_bar`, `status_bar`), как заголовок и
строка состояния в Zed.

**Скругления по Fluent.** Окно и карточки — 8 px (`radius.lg`), элементы
управления (кнопки, поля, переключатель, вкладки) — 4 px (`radius`). Окно
флайаута у Windows 11 скруглено системой; мы повторяем 8 px рамкой, чтобы
совпадало. (В спайке было 5/8 — в проекте 4/8.)

**Сетка отступов 4/8/12/16/24.** Внешние поля окна 16 px, расстояние между
карточками 12 px, внутри карточки 12 px, между подписью и полем 4 px, между
полями 12 px, между кнопками 8 px. Высота элементов управления 32 px
(Fluent «standard»), компактные кнопки в шапке 28 px. Никаких `px_3`
«на глаз»: каждое число — из этой шкалы. `gpui-component` даёт `Sizable`
(`small` = 28–32 px), этого хватает.

**Типографика — рампа Fluent, шрифт Zed.** Caption 13 px для подписей полей
и подстрок, Body 15 px для всего остального, Body Strong 15 px SemiBold для
имени программы и состояния, Subtitle 16 px SemiBold не нужен — окно
маленькое. Моно (Lilex 14) только в журнале. Семейство — IBM Plex Sans:
у Fluent это роль Segoe UI, не его начертание.

**Акцент — редко и по делу.** Акцентный цвет (`primary`: системный синий
macOS в тёмной, синий Zed в светлой) носят ровно три вещи: включённый
переключатель, одна главная кнопка открытой вкладки (`.primary()`) и
кольцо фокуса. Всё остальное — «standard»-кнопки: слой + обводка 1 px
(`Button` без варианта, он же `secondary`). Состояние связи говорит цветом
только кружок: серый / акцент / зелёный `success` / красный `danger`, текст
рядом — обычный.

**Фокус и клавиатура — насколько даёт набор.** Tab ходит по переключателю,
полям и кнопкам в порядке чтения (`tab_index` есть у `Switch`, `Input`,
`Button`), видимое кольцо фокуса 2 px `ring` появляется только от
клавиатуры (так делает `gpui-component`), переключатель и кнопки реагируют
на пробел, Esc прячет окно (как у флайаутов Windows). Вкладки `TabBar`
клавиатурой не переключаются — у `gpui-component 0.7.3` нет `tab_index` у
`Tab`, а рисовать свои вкладки нельзя (анти-цель). Это не must: окно
мышиное, как быстрые настройки Windows. *Решение автора спеки по вопросу
строителя.*

**Движение — короткое и служебное.** Появление флайаута без анимации
(GPUI показывает окно сразу; Windows сам анимирует его тень), переключение
вкладок мгновенное, переключатель и наведение — штатные переходы
`gpui-component` (`motion_tokens`, порядка 100–150 мс). Ничего не
«въезжает» и не пульсирует; занятость показывает `loading` у кнопки
(спиннер внутри кнопки — паттерн Fluent «progress in place»).

**Light dismiss.** Флайаут исчезает, когда человек щёлкает в любое другое
место, нажимает Esc или ✕; он не окно «приложения», его нет на панели
задач и в Alt+Tab (`PopUp`). Повторный щелчок по значку при открытом
флайауте закрывает его, а не открывает второй — это и есть правило 400 мс.

**Материал.** Fluent-флайауты рисуются на Mica/Acrylic. У GPUI есть
`WindowBackgroundAppearance::Blurred`; на Windows это не обещано, поэтому
по умолчанию `Opaque`, а `Blurred` — опциональная проверка в живом тесте:
если работает и не ломает текст, включить, иначе оставить непрозрачный
слой. Не блокирует ничего.

**Текст на русском, как у Fluent-приложений.** Короткие глаголы на
кнопках («Сохранить», «Проверить», «Установить», «Снять»), подписи полей
без двоеточий, подстроки — одним предложением без точки в конце,
сообщения об ошибках говорят, что сделать (это уже так в `gui.rs`,
не терять при переносе).

### Окно

`WindowOptions`: `kind: PopUp`, `titlebar: None`,
`window_decorations: Client`, `is_resizable: false`, `is_minimizable: false`,
`focus: true`, `show: true`, размер 380×640 логических пикселей. Положение —
правый нижний угол рабочей области с отступом 12 px:
`SystemParametersInfoW(SPI_GETWORKAREA)` и `GetDpiForSystem` из
`windows-sys` (физические → логические пиксели). На не-Windows —
`Bounds::centered`.

Корень — `gpui_kit::open_window(opts, cx, |window, cx| cx.new(|cx| Panel::new(window, cx)))`:
он сам заворачивает вид в `Root` (слои диалогов и уведомлений
`gpui-component`). Рамка окна 1 px `window.border`, скругление `rounded_md`,
`overflow_hidden`.

**Прятать, не закрывать программу.** `cx.set_quit_mode(QuitMode::Explicit)`:
без окон процесс живёт, выход — только пункт «Выход» в трее (и `quit`).
«Спрятать» = `window.remove_window()`; «показать» = открыть окно заново
(вид строится за миллисекунды, состояние живёт в глобале, см. ниже).
Прячем: по кнопке ✕, по потере активности
(`cx.observe_window_activation` + `!window.is_window_active()`), кроме
времени, пока открыт системный диалог выбора (`dialog_open`). Щелчок по
значку трея — `toggle`: если окно спряталось меньше 400 мс назад (щелчок по
значку сначала отнимает фокус), не показываем — человек хотел закрыть. Это
ровно та логика, что в `gui.rs` сейчас, без паузы в 250 мс.

### Трей

`tray-icon = "0.26"` (`default-features = false`) и его `muda`: те же
крейты, что внутри Tauri, без Tauri. Создаётся в главном потоке внутри
`Application::run`, до открытия окна. Меню: один пункт
«Подключить»/«Отключить» (надпись по состоянию, `MenuItem::set_text`),
«Проверить», «Открыть веб-клиент», разделитель, подменю «Тема»
(см. «Тема и шрифты»), разделитель, «Выход». Левый щелчок — `toggle`
окна, меню — по правому (`with_menu_on_left_click(false)`).

Значок — как сейчас: `icons/tray.png` плюс кружок в углу, рисуется в
памяти функцией `badge` (она и её тест остаются; меняется только тип
результата — `tray_icon::Icon::from_rgba`). Подсказка «1c-connect:
подключён / не подключён».

### Мост событий: один канал

Один `futures::channel::mpsc::unbounded::<Ev>()`, одна задача
`cx.spawn(async move |cx| while let Some(ev) = rx.next().await { cx.update(|cx| handle(ev, cx)) })`.
В канал пишут:

- трей: `TrayIconEvent::set_event_handler` и `MenuEvent::set_event_handler`
  (их зовёт WndProc трея на этом же потоке; `UnboundedSender` — `Send + Sync`);
- сеанс: `session::start(cfg, kit, sink, on_state)` — `on_state` и `Sink`
  шлют `Ev::Link(State)` и `Ev::Line(kind, text)` из потока туннеля;
- операции (`install`/`uninstall`) и проверка — из своих потоков, концовка
  `Ev::Done(Option<String>)` и `Ev::Checks(Vec<Check>)`.

Никакого опроса по таймеру. Это заменяет четыре события Tauri
(`conn:line`, `conn:state`, `conn:done`, `conn:run-check`) и дюжину
`invoke`.

### Состояние и вид

Глобал GPUI (`impl Global`) `Ui`: `kit`, `cfg`, `session: Option<Session>`,
`link: State`, `log: Vec<Line>` (с потолком, скажем, 2000 строк — старые
выбрасываются), `tray: TrayIcon`, `toggle: MenuItem`,
`window: Option<WindowHandle<Panel>>`, `hidden_at`, `dialog_open`,
`checks: Vec<Check>`, `ops: Vec<OpView>`, `busy: Option<&'static str>`.
Это тот же `Ui` из `gui.rs`, минус Tauri-типы.

`Panel` — единственный вид (`Render`), держит только `Entity<InputState>`
полей, созданные из `cfg` при открытии окна. Активная вкладка и счётчики
бейджей (непрочитанные строки журнала, проблемы проверки) живут в глобале
`Ui`, потому что окно при скрытии уничтожается, а человек ждёт, что
вернётся туда же, где был. Изменение глобала → `cx.refresh_windows()`.

**Параметры сохраняются кнопкой «Сохранить».** Решение заказчика
2026-10-18 (правка в коде поверх автосохранения): в плашке действий
вкладки «Параметры» одна акцентная кнопка «Сохранить», активна, пока поля
отличаются от сохранённых (`original: Host` в `Panel`). Нажатие → собрать
`Host`, `validate`, записать toml — как `save_cfg` (`project` и `tools`
переносятся из текущих параметров). Ошибка валидации — строкой в нижней
плашке, toml не пишется. Light dismiss при несохранённых полях теряет
набранное: окно уничтожается при скрытии; это осознанная цена за явное
сохранение. Подключение — только переключателем в карточке состояния.

Компоновка (сверху вниз), один в один с `ui/index.html`:

1. Шапка на `title_bar`: значок, «1c-connect», ✕ (ghost-кнопка).
2. Карточка статуса на `secondary`: кружок (серый / акцент «подключаюсь» /
   зелёный), состояние и подстрока (`State::label`, минуты, порты, причина
   повтора или отказа), `Switch` справа.
3. `TabBar`: Параметры, Расширение, Проверка (бейдж с числом проблем),
   Журнал (бейдж новых строк, пока вкладка не открыта).
4. Тело вкладки, единственное, что прокручивается:
   - **Параметры**: «Адрес среды и порт SSH», «Рабочее место» (select) и
     «Пароль рабочего места» в ряд, «База» с кнопкой выбора папки,
     «Пользователь базы» и «Пароль» в ряд, «Адрес публикации», «Каталог
     выгрузки конфигурации» с кнопкой выбора папки.
   - **Расширение**: список операций `common::run::status` — кружок по
     состоянию (`done`/`missing`/`drift`/`blocked`), заголовок, подробность.
   - **Проверка**: список `Check` после запуска; до — подсказка «Семь фактов
     снизу вверх; отчёт — last-check.txt в комплекте».
   - **Журнал**: моноширинные строки, цвет по виду (`ok`/`warn`/`fail`/
     `say`/`command`/`output`), автопрокрутка вниз при новых строках.
5. Нижняя плашка: слева итог последнего действия (или путь к комплекту),
   справа действия вкладки: Параметры — «Подключить»/«Отключить»;
   Расширение — «Снять» и «Установить»; Проверка — «Проверить»; Журнал —
   «Очистить». Во время операции кнопки вкладки заблокированы (`busy`).

Поведение действий — как в `app.js`: «Подключить» переводит на Журнал;
ошибка старта сеанса (нет toml, `server` из образца) — строкой `fail` в
журнал и показ окна; «Проверить» из трея показывает окно и запускает
проверку; «Открыть веб-клиент» — `cx.open_url(web_url)`.

### Диалоги

Выбор папки — `cx.prompt_for_paths(PathPromptOptions { directories: true, .. })`,
результат — `oneshot`, ждём в `cx.spawn`. На время диалога `dialog_open =
true`, после — `activate_window` у флайаута. Фильтра по расширению у GPUI
нет: выбор файла модели GGUF (если он понадобится в этом окне — сейчас
`pick("gguf")` есть, но в `index.html` не используется) проверяет расширение
после выбора.

### Что уходит

`tauri`, `tauri-build`, `tauri-plugin-dialog` из `Cargo.toml`;
`tauri.conf.json`, `capabilities/`, `gen/`; `ui/` (`index.html`, `app.css`,
`app.js`, `logo.png`). Фича `gui` остаётся, её состав: `gpui-kit`,
`tray-icon`, `futures`, `windows-sys` (уже в проекте). `icons/icon.png`,
`icon.ico`, `tray.png` остаются; значок окна — `WindowOptions.icon`.

**Значок exe.** `tauri-build` встраивал `icons/icon.ico` в ресурсы
бинаря; без него в Проводнике будет стандартная иконка. `build.rs`
остаётся, но маленький: под `feature = "gui"` на Windows зовёт
`embed-resource` с `.rc` из одной строки (`1 ICON "icons/icon.ico"`).
`embed-resource` уже в дереве зависимостей (`gpui-pre`, фича
`windows-manifest`), так что правило «без новых зависимостей» держится.
*Решение автора спеки по вопросу строителя.*

Манифест Windows (DPI-aware, common-controls v6) раньше клал `tauri-build`.
`gpui-pre` с фичей `windows-manifest` (в `default`) встраивает свой; если
живой тест покажет, что окно размыто на 125 %, добавить манифест в тот же
`.rc` — это запасной путь, не план.

### CI и сборка

`build.yml` не меняется по форме: Windows собирает с окном, Linux —
`--no-default-features` (теперь это не webkit2gtk, а GPUI-на-Linux, который
нам не нужен). Комментарий в workflow и в `Cargo.toml` обновить. Кэш cargo
на Windows-раннере стоит включить, если его нет: холодная сборка GPUI
заметно длиннее Tauri.

### Проверки кода

- `badge`: тест остаётся.
- Тема: тест, что `macos-classic.json` парсится `ThemeSet` и содержит ровно
  одну светлую и одну тёмную тему.
- `session::State`, `verify`, `ops_host` — без изменений, их тесты живут.
- Живой тест — руками, по списку из «Спайка»: показ, переключатель, потеря
  фокуса, щелчок по значку, диалог папки, «Выход».

## Спайк: что проверено (2026-10-16, эта машина, Windows 11, 2560×1440, 125 %)

`spike-gpui/`, отдельный крейт, `gpui-kit 0.7.3` + `tray-icon 0.26.1`:

- Собирается без cmake/nasm; первая сборка около 10 минут, далее секунды.
- Трей создаётся в главном потоке рядом с циклом GPUI; щелчок по значку
  (в переполнении панели задач) приходит `TrayIconEvent::Click`, обработчик
  через канал будит задачу GPUI — окно показывается. Меню и `set_text`
  работают.
- Окно `PopUp` + `Client` получает фокус при показе, прячется по
  `observe_window_activation`, процесс живёт без окон при
  `QuitMode::Explicit`.
- Ловушка: отладочная сборка — консольная; `Start-Process` создаёт окно
  conhost, оно через полторы секунды забирает фокус, флайаут прячется.
  Со `windows_subsystem = "windows"` сценарий чистый: показ → переключатель →
  «подключён» → потеря фокуса → спрятано → щелчок по значку → показано.
- Тема `macos-classic` светлая и тёмная, шрифты IBM Plex Sans / Lilex,
  кириллица — рендерится; скриншоты в scratchpad сессии (`mac_dark.png`,
  `mac_light.png`).

Что спайк не проверял: диалог выбора папки (API есть, поведение фокуса после
него — по той же логике, что `dialog_open` в Tauri), размер релизного бинаря
(измерить первым шагом плана), работу на 100 % масштабе и на втором
мониторе.
