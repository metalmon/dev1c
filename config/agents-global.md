# Эта среда

Debian в контейнере, графическая сессия по RDP, **интернета нет**. Платформа 1С
в образ не входит.

Прежде чем сказать «такого инструмента здесь нет», проверь: `command -v имя`.

## Чем запускать код на языке 1С

`oscript` — OneScript 2.2, независимая реализация языка 1С на .NET. Работает на
Linux, платформа 1С ему не нужна:

```
oscript скрипт.os
```

Это **не** JScript и **не** Node.js: Windows Script Host, `cscript` и wine здесь
ни при чём и не требуются. Пакеты OneScript ставятся через `opm` (только из
локального кеша, сеть закрыта).

Расширения в экосистеме 1С ровно такие:

| Расширение | Что это |
|---|---|
| `.os` | скрипт OneScript — так называй файлы, которые запускаешь через `oscript` |
| `.bsl` | модуль конфигурации: выгрузка через конфигуратор или EDT |

Других не выдумывай. Редактор определяет язык по расширению, поэтому файл с
придуманным расширением остаётся без подсветки, подсказок и анализатора — хотя
`oscript` его и запустит.

## Код на 1С: сначала проверь, потом отдавай

Это не стиль, а замер на банке 1С-задач: **второй проход по своему же коду
вытаскивает больше трети решений, которые с первого раза были неверны** —
больше, чем любая подсказка в промпте. Поэтому порядок такой:

1. написал — **запусти или проверь**: алгоритмику через `oscript скрипт.os`,
   синтаксис модуля через `oscript -check файл.os`, диагностики через
   `bsl-analyzer` (он же LSP в редакторе);
2. упало — читай сообщение и правь причину, а не симптом;
3. **незнакомое имя платформы спрашивай в `bsl-reference`** (`syntax_help`), а
   не вспоминай. Ответ «Сущность платформы не найдена» значит, что такого имени
   в 1С НЕТ — ищи настоящее, не подставляй похожее.

Чаще всего придумываются кальки с других языков. Правильно так:

| Калька | В 1С |
|---|---|
| `Стр(X)` | `Строка(X)` |
| `Длина(С)` | `СтрДлина(С)`, у коллекций `.Количество()` |
| `Заменить(...)` | `СтрЗаменить(С, Что, НаЧто)` |
| `Остаток(A, B)` | оператор `A % B` |
| `Массив.Сортировать()` | **такого метода нет** — сортируй через `ТаблицаЗначений` |
| группировка ТЗ своими руками | `ТЗ.Свернуть("Группировки", "Суммируемые")` |

Остаток дат — в **секундах**: `Дата + 86400` это сутки, разность двух дат даёт
секунды.

Оговорка про чужую конфигурацию: низкий режим совместимости скрывает часть
платформенных имён (например `СтрНайти`, `СтрРазделить`, побитовые и регулярные
выражения). Сам не угадывай — `bsl-analyzer` знает режим из `Configuration.xml`
выгрузки и скажет, если имя в этом режиме недоступно.

## Какой инструмент на каком шаге

Инструментов здесь много, и часть выбора уже сделана за тебя. Бери основной;
остальные — только по условию в правой колонке.

| Что нужно | Чем | Остальные |
|---|---|---|
| имя платформы, сигнатура | `syntax_help` сервера `bsl-reference` | `bsl_syntax_help` сервера `1c` — когда нужен пример кода |
| имени не знаешь | `search` с `action=find_docs` там же | первые секунды после запуска он отвечает «Search index is being built» — повтори, это не отказ |
| структура конфигурации | `rg` и чтение файлов по выгрузке в `~/project` | `get_metadata_tree`, `get_object_structure`, `get_form_structure` сервера `1c` — когда выгрузки нет |
| данные базы | `execute_query` сервера `1c` | `validate_query` — пока запрос только пишется |
| проверить алгоритм в отдельном скрипте | `oscript -check файл.os`, затем `oscript файл.os` | — |
| проверить модуль конфигурации | диагностики `bsl-analyzer` в редакторе, затем `validate_syntax_check` | `oscript -check` **не применяй к модулю конфигурации**: метаданных он не знает и назовёт `Документы` неизвестным символом в исправном коде |
| запустить тесты | фреймворк, который стоит в базе проекта: `test_yaxunit`, `test_xunit` или `test_vanessa` | какой именно — свойство базы: выясни, а не перебирай. Не стоит ни один — проверяй алгоритмику `oscript` и называй это проверкой, а не тестом |
| долгая операция | `background=true`, затем `task_status` и `task_result` | `task_cancel`, если нужно прервать |
| конфигурация в git | `project_status`, `project_pull`, `project_push` | `git` в терминале — для своих файлов, не для выгрузки |

Серверы `1c` и `vrunner` отвечают, когда поднят канал к машине с платформой.
Ошибка подключения значит, что канала нет, а не что инструмент сломан: бери
то, что работает без него — выгрузку, `rg`, `oscript`, `bsl-reference`.

Чего здесь нет и не будет: `its_help` (просит платный токен code.1c.ai, а сети
нет), веб-поиск и загрузка страниц. Обходных путей не ищи — скажи, что нужен
канал или платформа.

## Остальные инструменты

| Для чего | Чем |
|---|---|
| скрипты | `pwsh` (PowerShell 7), `python3`, `oscript` |
| git и его сервер | `git`, `tea` (CLI к локальному Gitea, вход уже настроен) |

## Как работать с конфигурацией через git

Конфигурация базы живёт в Gitea: репозиторий `dev1c/<база>`, у каждого
рабочего места своя ветка — `dev1`, `dev2`, `dev3` (твоя — по логину).
`main` — общая, в неё сливают руками.

1. Начало: `git clone -b dev<N> http://localhost:3000/dev1c/<база>.git`
   (вход уже настроен) или `git pull` в уже склонированном.
2. Правки — в `src/`, обычные коммиты и `git push` в свою ветку.
3. Загрузка в базу идёт на машине разработчика инструментами MCP `vrunner`
   (если сервер отвечает): сначала `project_pull`, затем `cf_load`
   (инкрементом по `src/ConfigDumpInfo.xml` — этот файл не править руками),
   потом `validate_syntax_check`, потом тесты тем фреймворком, который стоит
   в базе (см. карту выше — угадывать его нельзя). Выгрузка обратно:
   `cf_decompile`, затем `project_push`.
4. Длинные команды уходят в фон: ответ с `taskId`, дальше `task_status` и
   `task_result`; не повторяй команду, пока задача выполняется.
5. «занято: идёт …» — на машине уже идёт операция; подожди и повтори.
   «закройте Конфигуратор» — у разработчика открыт Конфигуратор; скажи ему.

## Шум в выводе терминала

Строка вида

```
/bin/sh: 1: Cannot set tty process group (No such process)
```

к результату команды отношения не имеет. Это предупреждение оболочки о
управлении задачами внутри контейнера, где нет обычного init. Команда при этом
выполняется. Не пытайся её «исправить» и не считай признаком отказа — смотри на
код возврата и на остальной вывод.

## Платформа 1С

Конфигуратор, `1cv8` и `vanessa-runner` живут на машине разработчика, а не
здесь. Доступ к ним — только через обратный SSH-туннель, и только если он
поднят. Если туннеля нет, честно скажи, что операция требует платформы, вместо
того чтобы искать обходной путь.
