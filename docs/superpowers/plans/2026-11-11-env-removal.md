# Среда разработки уезжает из программы целиком

План. Проектирование, кода здесь нет. Решение владельца 11.11.2026 («Да» на вопрос «начинать удаление?»), курс — `memory/course-agents-to-1c-any-direction.md`: коннектор перестал быть приставкой к пилоту, и машина-среда с тремя рабочими местами, ssh-туннелем и своей Gitea уходит вся.

Основание по сочетаниям — `docs/superpowers/specs/connection-combinations.md`. Основание по окну — `docs/superpowers/specs/interface-blocks.md`.

## 1. Что заставило начать именно сейчас

Замер 11.11, отдельная копия (`C:\live-a`), карточка «принимаю подключения, база здесь» — это сторона **2** пары A и та же роль у стороны **4** пары B, основного сценария:

- поля среды пустые → сеанс отказывает на старте: `рабочее место — это ваш логин в среде: dev1, dev2 или dev3`;
- поля подставные (`127.0.0.1:3393`, `dev1`) → сеанс умирает на ssh: `нет связи с сервером… (os error 10061)`.

**То есть сторона с базой в обеих законных парах сеанс не поднимает вовсе.** `Serving` не публикуется, и вызовам по каналу приземляться не на что — шаг 4 плана пары B доказать живым прогоном нельзя, пока это так.

Причина одна и называется привычно: **две меры на один вопрос, вывернутые наизнанку** — одно значение `mode = "tunnel"` значит сразу две разные вещи (старая среда по ssh и новая пара по каналу), и оба читателя — `validate` и развилка транспорта в `session.rs` — понимают его как среду.

## 2. Как это выражается типами

### 2.1. Транспорт выбирает ОДНА ось

```rust
// session.rs — после удаления
let toward = if cfg::Combo::of(cfg.current()).base_is_here() { Toward::Child } else { Toward::Channel(..) };
listen::run(serve, active_ports, toward, on_event, stop_rx).await
```

Сегодня развилка трёхходовая, и третий ход — туннель. После удаления ходов остаётся два, и оба отвечают на вопрос из спеки сочетаний: **база здесь или на другом компьютере**. «Поднять ssh в среду» становится невыразимо, а не запрещено условием.

Сочетание **Alone** в этой развилке больше не отдельный случай: база у него здесь, значит `Toward::Child` — тот же местный слушатель, что и у сочетаний 2 и 4. Разница между 1 и 2/4 — есть ли вторая сторона, а это вопрос канала, не транспорта моста.

### 2.2. Поля среды уходят из карточки

Из `cfg::Connection` исчезают: `server`, `gitea`, `password` (пароль рабочего места в среде), `workstation`. Вместе с ними:

- две проверки `validate` (`[workstation]`, `[server]`) — те самые, что отказали замеру;
- `mode_needs_env` — вопрос «нужна ли среда» перестаёт существовать;
- `number_of` и всё, что считало номер рабочего места;
- `derived_gitea`, `gitea_to_write`, `gitea_probe`, `Layout::NoGitea`, факт «Gitea» в проверке.

`mode` остаётся с двумя значениями, `"local"` и `"tunnel"`, и это долг **на отдельный шаг**: слово «tunnel» после удаления туннеля — ложь, и означает оно «пара по каналу». Переименование — шаг 6, последним, когда ни один читатель среды уже не мешает.

### 2.3. Старый файл параметров не ломается молча

Разбор `1c-connect.toml` отказывает незнакомым ключам (проверено: `unknown field connections`). После удаления **живой файл владельца с ключом `server` стал бы отказом при старте** — то есть программа, которая вчера работала, сегодня не поднимется и не скажет почему.

Поэтому в разборе остаётся **список ушедших ключей** и отдельные слова на каждый: «ключ `server` больше не читается: среда разработки удалена из программы, подключение идёт по каналу. Можете убрать его из файла». Не миграция (в проде никого нет, `memory/no-users-in-production.md`), не тихий `#[serde(default)]`, а предложение словами — десяток строк и один тест.

## 3. Что следует за удалением, но решается отдельно

**`export` / `import`.** Их вторая половина — `git push`/`git pull` в Gitea среды. Без среды у remote нет дома. Местные половины (`cf_decompile → src`, `cf_load` из `src`) — это и есть «Выгрузка/Загрузка», которые владелец велел в интерфейсе **сохранить**, но перенести в другое место (его слова 10.11). Поэтому:

- remote-половина уходит с Gitea;
- местная остаётся как есть, и её переезд по окну — та задача, которая уже ждёт решения о вкладке «Инструменты»;
- локальный git в папке проекта остаётся: он ничего не ломает и ничьего адреса не требует.

**Подкоманда `connect`** («Поднять туннель и мост») после удаления туннеля держит только мост — переименование в её же шаг слов.

## 4. Порядок работ

Каждый шаг кончается зелёными гейтами (`cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `cargo fmt --check`) и своим коммитом. Шаги 0 и 1 вместе снимают препятствие замера из раздела 1 — живой прогон шага 4 пары B возможен сразу после них.

**Сделано 11.11** — шаги 0–6, тремя коммитами (`fabc204`, `5acf032`, `c89899d`): транспорт по одной оси, `tunnel.rs` и поля среды удалены, Gitea и удалённая половина обмена ушли, слова догнали дело. Замер раздела 1 повторён на новой сборке: сеанс поднимается («MCP включены: порты 7771 и 7781»).

**Остался долг, названный в разделе 2.2:** значение `mode = "tunnel"` теперь значит «у соединения есть вторая сторона», и слово лжёт. Переименование — отдельная работа: оно трогает файл человека, и делать его заодно с удалением нельзя.

| Шаг | Что | Чем проверяется |
|---|---|---|
| **0** | Транспорт по одной оси: `base_is_here()` → `Child`, иначе `Channel`. Туннельная ветка вызывается из одного места — её и снимаем | тест на развилку: у сочетаний 1, 2, 4 — `Child`, у 3 и 5 — `Channel` |
| **1** | Поля среды уходят из `Connection`, с ними обе проверки `validate` и слова об ушедших ключах | замер раздела 1 повторяется: сеанс поднимается |
| **2** | `tunnel.rs` удаляется физически (475 строк), с ним `Incoming`, `workstation_busy_text`, остатки номера рабочего места | компиляция; ни одного `tunnel::` в дереве |
| **3** | Gitea и её следы: вывод адреса, проба, факт проверки, `Layout::NoGitea`, remote-половина `export`/`import` | тесты фактов и `flow` |
| **4** | Окно: блок среды, его поля и факты, поток «Установить» в части среды | закон окна (`interface-blocks.md`), живой снимок |
| **5** | Подкоманды: `connect` без туннеля, `example` без полей среды, справка | `--help`, `check` на чистом комплекте |
| **6** | Слова: `mode` получает честное значение вместо `"tunnel"`, докстроки и спеки перестают поминать среду | `grep` по дереву: ни «среда разработки», ни dev1–dev3 |

## 5. Чего НЕ делать

- **Не трогать мост.** `bridge.rs` о транспорте не знает и знать не должен; удаление среды не вправе изменить в нём ни строки.
- **Не выдумывать признак «это ещё среда»** вроде «`server` не пуст». Он был бы третьей мерой на тот же вопрос и умер бы вместе с шагом 1.
- **Не чинить заодно вкладку «Инструменты»** и переезд выгрузки/загрузки: решение по ней за владельцем и ждёт отдельно.
- **Не переписывать файл владельца.** Программа говорит про ушедшие ключи словами; убирает их человек сам (`memory/never-overwrite-user-config.md`).
