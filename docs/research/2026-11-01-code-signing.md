# Подпись кода для 1c-connect: сертификаты, Касперский, юрисдикция

Дата: 2026-11-01. Факты из сети, со ссылками. Где источника нет — написано «не нашёл».

## 1. Сертификаты подписи кода: виды и цена

**OV (Organization Validation)** — обычный сертификат подписи кода, проверяется только организация/физлицо-заявитель.
**EV (Extended Validation)** — расширенная проверка, дороже.

Цены за год (2026, у реселлеров/прямых продавцов):

- Sectigo/Comodo OV — от **$219–225/год** ([SSL Dragon](https://www.ssldragon.com/ssl-certificates/code-signing/), [SSL2BUY](https://www.ssl2buy.com/sectigo-code-signing-certificate.php))
- SSL.com OV — от **$129/год** (1 год), дешевле при оплате на несколько лет вперёд ([SSL.com OV](https://www.ssl.com/products/software-integrity/code-signing/ov/))
- DigiCert OV — **$399–575/год** ([SignMyCode](https://signmycode.com/digicert-code-signing), [CompareCheapSSL](https://comparecheapssl.com/digicert-code-signing-certificate-price-renewal-best-deals/))
- Sectigo/Comodo EV — от **$279–325/год** ([SignMyCode](https://signmycode.com/sectigo-ev-code-signing), [SSL2BUY](https://www.ssl2buy.com/sectigo-ev-code-signing.php))
- DigiCert EV — **$559–685/год** ([SignMyCode](https://signmycode.com/digicert-ev-code-signing))

**Аппаратный носитель — с 1 июня 2023 обязателен**, и это касается **и OV, и EV**, не только EV. Требование CA/Browser Forum: закрытый ключ должен генерироваться и храниться в сертифицированном крипто-модуле (минимум FIPS 140-2 level 2 / Common Criteria EAL4+); экспорт ключа из устройства запрещён ([Entrust](https://www.entrust.com/blog/2022/09/ca-browser-forum-updates-requirements-for-code-signing-certificate-private-keys), [Encryption Consulting](https://www.encryptionconsulting.com/understanding-the-ca-browser-forum-code-signing-requirements/)). Варианты исполнения:
- USB-токен от CA — у некоторых продавцов входит в цену (Sectigo/Comodo, FairSSL — токен SafeNet eToken включён); у DigiCert токен — отдельно, **+$120** ([my-ssl.com](https://my-ssl.com/learn/code-signing-certificate-price));
- облачный HSM (платная подписывающая услуга CA) — см. ниже.

**Последствие для CI**: раз ключ физически не экспортируется из токена/HSM, «просто подписать бинарник на сборочном сервере файлом .pfx» с 2023 года не работает. Нужен либо физический токен, подключённый к машине, которая подписывает (неудобно для CI), либо платная облачная служба подписи:
- DigiCert KeyLocker — **$65/мес** за OV-сертификат с облачным HSM, **$83/мес** за EV, лимит 1000 подписей за жизнь сертификата, докупка пачками сигнатур отдельно ([docs.digicert.com](https://docs.digicert.com/en/digicert-keylocker/overview/licensing.html), [SSLmarket](https://www.sslmarket.com/ssl/digicert-keylocker-cloud-hsm))
- SSL.com eSigner — аналогичная облачная подпись без физического токена, цены по запросу ([SSL.com eSigner](https://www.ssl.com/guide/esigner-pricing-for-code-signing/))

## 2. Поведение Windows: OV vs EV — разницы почти не осталось

Официальная документация Microsoft ([SmartScreen reputation for Windows app developers](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)):

> EV certificates no longer bypass SmartScreen. Years ago, signing files with an EV code signing certificate would result in positive SmartScreen reputation by default, but this behavior no longer exists.

Таблица из этого документа:
| Тип сертификата | Поведение при первом скачивании |
|---|---|
| Microsoft Store | без предупреждения |
| Действующий сертификат (OV или EV) | предупреждение — приложение «неизвестно», пока не накопится репутация; имя издателя показывается верифицированным |
| Без подписи | предупреждение «Windows защитил ваш ПК», нужно нажать «Выполнить в любом случае»; групповая политика может запретить это вовсе |
| Самоподписанный сертификат | то же, что без подписи |

Вывод Microsoft: раньше EV давал немедленную репутацию, теперь — нет, репутация у OV и EV строится одинаково, по накоплению скачиваний/отсутствию жалоб. Платить за EV ради того, чтобы избежать предупреждения SmartScreen, по документации уже не оправдано.

## 3. Подписание как услуга от Microsoft (Azure Trusted Signing → Azure Artifact Signing)

Переименована в 2026 в **Azure Artifact Signing** ([MS Learn: What is Artifact Signing?](https://learn.microsoft.com/en-us/azure/artifact-signing/overview)).

Цена: Basic — **$9.99/мес** (5000 подписей/мес), Premium — **$99.99/мес** (100 000 подписей/мес), сверх квоты — **$0.005/подпись** ([infoworld.com](https://www.infoworld.com/article/2337355/understanding-microsofts-trusted-signing-service.html), [gdgsoft.com](https://www.gdgsoft.com/faq/azure-trusted-signing-cost-effective-exe-code-signing)). Это дешевле любого традиционного сертификата с облачным HSM.

**Условия допуска — и здесь стоп для этого проекта:**
- Организации — только из **США, Канады, ЕС, Великобритании**, с подтверждённой историей регистрации **3+ года** (проверяется по бизнес-реестрам, налоговым записям, DUNS и т.п.).
- Физлица-разработчики — только из **США и Канады**.
([MS Q&A: Eligibility confirmation](https://learn.microsoft.com/en-us/answers/questions/6049097/eligibility-confirmation-azure-artifact-signing-fo), [MS Q&A: individual identity](https://learn.microsoft.com/en-us/answers/questions/5810735/cant-create-a-new-trusted-signing-individual-ident))

Ни Грузия, ни Россия в списке допущенных юрисдикций не встречаются ни для организаций, ни для физлиц — прямого подтверждения «Грузия запрещена явным списком» не нашёл (Microsoft не публикует закрытый список стран-исключений), но и подтверждения, что Грузия или Россия допущены, не нашёл. Практический вывод от сообщества: разработчикам вне США/Канады/ЕС/UK рекомендуют обычный OV-сертификат у CA, а не Trusted/Artifact Signing ([MS Q&A thread](https://learn.microsoft.com/en-us/answers/questions/5810735/cant-create-a-new-trusted-signing-individual-ident)). **Вывод: самый дешёвый путь владельцу недоступен по юрисдикции.**

## 4. Касперский: что весит сильнее подписи

У Касперского есть бесплатная программа **Allowlist** ([kaspersky.com/partners/allowlist-program](https://www.kaspersky.com/partners/allowlist-program)):

- **Участие бесплатное.**
- Требования к участнику:
  - ссылка на действующий сайт компании **с юридическим адресом**, понятные элементы интерфейса сайта;
  - само ПО: не копирует интерфейс сторонних продуктов, не выдаёт поддельные системные сообщения, не рекламирует посторонний софт/ресурсы, не обращается на вредоносные ресурсы, не вымогает деньги ложными формулировками; если это инструмент удалённого администрирования — не должен иметь скрытого удалённого доступа и не должен ранее использоваться злоумышленниками;
  - **цифровая подпись компании (если есть) не используется другими вендорами и не скомпрометирована** — формулировка «при наличии» означает, что подпись не строго обязательна для участия, но если она есть, к ней тоже есть требование чистоты.
- После одобрения ПО попадает в список известного легитимного софта «Лаборатории Касперского», что должно снять ложные срабатывания независимо от наличия EV/OV-подписи как таковой.

Это сильно совпадает с опасением владельца: именно договорённость с Касперским (бесплатная, через Allowlist) может решить проблему конкретно на бухгалтерских терминальных серверах, а не покупка сертификата сама по себе. Подпись здесь — предпосылка доверия (её отсутствие не блокирует Allowlist явно, но повышает шанс, что файл сочтут подозрительным ещё до рассмотрения заявки), а не формальное условие участия.

Отдельно: подача конкретного файла на анализ ложного срабатывания — через [Kaspersky Threat Intelligence Portal](https://opentip.kaspersky.com/) (кнопка «Submit to reanalyze») или поддержку — бесплатна, но это разовая процедура на файл/версию, а не постоянная белая запись, в отличие от Allowlist.

## 5. Юрисдикция — решающий фактор

**Западные CA (DigiCert, Sectigo/Comodo, вероятно GlobalSign как общее следствие экспортного контроля США) не продают сертификаты (включая подпись кода) в Россию и Беларусь** с 2022 года, и это не смягчилось к 2026:

- DigiCert: полное эмбарго — Куба, Иран, КНДР, Сирия, Крым/ДНР/ЛНР; секторальные санкции — **Россия, Беларусь, Венесуэла** — «DigiCert приостанавливает выпуск и переоформление всех типов сертификатов, связанных с Россией и Беларусью», включая организации с адресом в РФ/РБ ([DigiCert: Embargoed Countries & Regions](https://knowledge.digicert.com/solution/embargoed-countries-and-regions)).
- Sectigo: **Россия и Беларусь в общем «Banned Country List»** — сертификаты любого типа не выпускаются вовсе, наравне с Кубой, Ираном, КНДР, Сирией ([Sectigo: Banned Country List](https://www.sectigo.com/knowledge-base/detail/Banned-Country-List-1527076085907)).
- В 2026 ситуация обострилась: GlobalSign начал принудительно отзывать уже выданные SSL-сертификаты у российских организаций из-за новых правил CA/Browser Forum о проверке по санкционным спискам США/ЕС ([te-st.org](https://te-st.org/2026/06/16/globalsignoff/), [РБК](https://amp.rbc.ru/rbcnews/technology_and_media/13/06/2026/6a2d12da9a7947f7d5334aa0)). Это про TLS, но проверка по санкционным спискам — та же механика KYC, что и для code signing.
- Россия в ответ строит собственную инфраструктуру подписи кода («Единое пространство доверия», Отраслевой технологический удостоверяющий центр — ОТУЦ) с участием ФСБ, Минцифры, ФСТЭК, CryptoPro, «Лаборатории Касперского» и других; тестирование шло на ноябрь 2025 ([xakep.ru](https://xakep.ru/2026/06/23/code-signing/)). **Такой сертификат не входит в доверенные корни Windows** — прямого официального подтверждения от Microsoft не нашёл, но факт общеизвестный и логически следует: ОТУЦ/НУЦ Минцифры не являются членами Microsoft Trusted Root Program, поэтому подписанный ими бинарник в Windows будет выглядеть как неподписанный или с недоверенным издателем.

**Грузия в банлистах не встречается ни у DigiCert, ни у Sectigo.** Прямого подтверждения вида «заявителям из Грузии сертификаты продаются без ограничений» не нашёл (CA не публикуют позитивный список «кому можно» — только негативный список запрещённых стран), но отсутствие Грузии в обоих найденных банлистах означает, что формальных ограничений не видно. **Практический вывод: если юрлицо/ИП, на которое покупается сертификат, зарегистрировано в Грузии (не в России), путь через Sectigo/SSL.com/DigiCert открыт; если в России — закрыт у всех крупных западных CA.**

## 6. Альтернативы

- **Без подписи вообще.** По документации Microsoft — предупреждение «Windows защитил ваш ПК» при каждом скачивании и запуске, пока нет накопленной репутации; групповая политика на терминальном сервере (это прямо упомянуто в документации) может блокировать запуск совсем, без возможности пользователя нажать «выполнить всё равно» ([MS Learn SmartScreen reputation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)). Для бухгалтера без прав администратора на RDP это означает «не запустится» — ровно опасение из вопроса.
- **Самоподписанный сертификат.** По найденным источникам — Windows не доверяет ему по умолчанию, поведение SmartScreen идентично отсутствию подписи ([MS Learn SmartScreen reputation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation), [gist.github.com/MangaD](https://gist.github.com/MangaD/e8f67fb39a35abdbf4ad26711c5957cc)). Даёт ложное ощущение решения проблемы, не решая её.
- **Microsoft Store / winget.** Публикация в Store полностью снимает предупреждения SmartScreen — пакет подписывается сертификатом Microsoft при переупаковке, отдельный сертификат не нужен ([MS Learn SmartScreen reputation](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation)). Но: это магазинная модель дистрибуции (MSIX/упаковка, политика Store), а не «принести .exe комплектом», что прямо противоречит способу распространения 1c-connect (ставится комплектом на терминальные серверы, которыми управляют IT-администраторы клиентов, не через Store). winget как публичный репозиторий манифестов сам по себе не подписывает бинарник — подпись всё равно нужна от издателя.

## Короткий ответ

**Сколько это стоит в год:** OV-сертификат с аппаратным токеном — от **≈$130–220/год** (SSL.com, Sectigo/Comodo); нужен физический USB-токен (часто включён, иначе ещё ~$100–120) или облачная подпись (DigiCert KeyLocker от $65/мес). EV дороже (от ~$280/год), но по документации Microsoft с 2024 он **не даёт немедленной SmartScreen-репутации** — платить больше за это основания нет.

**Самый дешёвый путь Microsoft (Azure Trusted/Artifact Signing, от $9.99/мес) владельцу недоступен**: допуск только для организаций из США/Канады/ЕС/UK (3+ года регистрации) и физлиц из США/Канады — ни Грузия, ни Россия туда не входят.

**Юрисдикция — развилка.** Западные CA (DigiCert, Sectigo) официально не продают сертификаты заявителям из России и Беларуси — это подтверждено их собственными списками и обострилось в 2026 (отзыв уже выданных сертификатов). Грузия в этих списках не фигурирует. Значит: если покупать сертификат на юрлицо/ИП, зарегистрированное в Грузии — путь открыт у обычных западных CA (SSL.com/Sectigo, от ~$130–220/год). Если юрлицо российское — ни один крупный западный CA сертификат не продаст; остаётся только российская инфраструктура (ОТУЦ/НУЦ Минцифры), которая не входит в доверенные корни Windows и проблему SmartScreen/Касперского не решает.

**Касперский может оказаться важнее подписи.** У них есть бесплатная программа **Allowlist** (kaspersky.com/partners/allowlist-program): нужен только работающий сайт компании с юридическим адресом и ПО, которое не похоже на обманное/вредоносное; цифровая подпись упомянута как «если есть» — то есть не строго обязательна для подачи заявки, но раз сертификат всё равно нужен против SmartScreen, разумно подавать на Allowlist уже с подписанным билдом.

**Рекомендация:** оформить OV-сертификат (SSL.com или Sectigo/Comodo, ~$130–220/год) на юрлицо/ИП в Грузии, с физическим токеном или без (решить по удобству CI — физический токен проще для ручных релизов, облачная подпись/KeyLocker — если нужна автоматическая сборка), и параллельно — бесплатно подать приложение в программу Kaspersky Allowlist. EV и Azure Artifact Signing не рассматривать: первый не даёт выигрыша по SmartScreen, второй недоступен по юрисдикции. Открытый вопрос, требующий проверки у самого CA перед покупкой: принимает ли выбранный продавец оплату и верификацию именно от грузинского юрлица/ИП конкретно владельца (общий банлист не включает Грузию, но индивидуальную verification CA делает отдельно для каждого заказа).
